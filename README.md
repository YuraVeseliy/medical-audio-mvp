# Медицинский аудиомодуль: полная транскрибация

Текущий объём ДЗ: **записать разговор или загрузить файл → получить полную расшифровку → проверить и исправить текст → сохранить результат**.

Авторы ВКР: Юрий Черных и Михаил Бурундуков. Это учебная часть сервиса для ОКБ №1. Для проверки используются вымышленные диалоги. Модель может ошибаться в словах, отрицаниях, терминах и числах; текст проверяет человек.

В текущем модуле нет Qwen, выделения жалоб/анамнеза, проверки врачебного протокола и постановки диагноза. Предшествующая версия с извлечением сведений сохранена в Git на `22ab86697515260ef56e37ded77c32e04d48e8c6`. Её отчёты и измерения относятся к старому объёму. Актуальная спецификация: [docs/asr-plan.md](docs/asr-plan.md).

## Установка и запуск

Проверенная платформа: Windows x64, Python 3.12 с Tcl/Tk, локальный CPU. Для первоначальной установки нужен интернет.

```powershell
git clone https://github.com/YuraVeseliy/medical-audio-mvp.git
cd medical-audio-mvp
```

Запустите `setup.cmd`, затем `launch.cmd`. Установка создаёт `.venv`, ставит закреплённые зависимости и загружает только Whisper small. Остальные модели устанавливаются явно. Открытие окна само по себе не включает микрофон и не начинает обработку.

```powershell
# Одна дополнительная конфигурация
.\.venv\Scripts\python.exe scripts\setup_asr_models.py --model gigaam-ctc

# Все восемь: потребуется несколько гигабайт и время на загрузку
.\.venv\Scripts\python.exe scripts\setup_asr_models.py --model all
```

Модели, окружение и личные записи не входят в Git. Источники, ревизии и суммы — `configs/asr-models.json`, фактическая установка — `.runtime/manifests/`. Инференс использует локальные файлы; загружать модели во время замеров не следует.

Новая версия проверяется из исходников. Старый portable EXE с Qwen относится к предыдущей версии и не является сборкой текущего модуля.

## Первый сценарий в приложении

1. Выберите распознаватель в списке. Для начала установлен Whisper small.
2. Нажмите «Загрузить аудиофайл…» и выберите WAV, M4A, MP3, FLAC, OGG, MP4 или MKV с аудио.
3. Нажмите «Обработать аудио». Первый вызов включает загрузку весов, дальнейшие используют загруженную модель.
4. Слева находится исходное распознавание. Справа можно исправить весь текст. Исправления не переписывают исходный результат.
5. «Экспорт TXT…» сохраняет текущий текст UTF-8. «Сохранить сеанс…» сохраняет JSON с исходником, правками, моделью и сведениями обработки.
6. Выполните «Новый сеанс», затем «Открыть сеанс…» и проверьте восстановление правок.

Для записи нажмите «Обновить устройства», выберите микрофон, затем «Начать запись». После «Остановить и сохранить…» захват завершается до выбора пути. Если выбор пути отменён, остановленный буфер можно сохранить позже или явно удалить.

Файлы сеанса версии 2 относятся к полной транскрибации. JSON версии 1 с разделами формы открывается прежней версией приложения; новая версия сообщает о неподдерживаемом формате.

## Какие варианты сравниваются

| ID | Конфигурация |
|---|---|
| whisper-base | Whisper base, faster-whisper CPU int8 |
| whisper-small | Whisper small, faster-whisper CPU int8 |
| whisper-medium | Whisper medium, faster-whisper CPU int8 |
| vosk-small | Vosk small-ru-0.22 |
| vosk-large | Vosk ru-0.42 |
| gigaam-ctc | GigaAM v3 CTC, ONNX int8 |
| gigaam-rnnt | GigaAM v3 RNN-T, ONNX int8 |
| gigaam-e2e-rnnt | GigaAM v3 E2E RNN-T, ONNX int8 |

Это восемь конфигураций трёх семейств моделей. faster-whisper и onnx-asr — способы выполнения моделей. GigaAM используется в конкретном стороннем ONNX-экспорте: его источник и версия отражаются в результате.

## Самостоятельное сравнение

Подготовьте отдельную папку с десятью записями: dev01/dev02, dialog01..dialog06, control01/control02; TXT называются так же. Регистр Control02 нормализуется по ID. Оригиналы сохраняются, преобразования выполняются в новой папке.

```powershell
.\.venv\Scripts\python.exe scripts\prepare_human_data.py --audio-dir C:\Audio --reference-dir C:\Texts --out user_data\dataset-v1 --confirmed-references --executor "Юрий"
```

Флаг `--confirmed-references` указывайте после собственного прослушивания и сверки: сценарий чтения не становится эталоном автоматически. Если слова отличаются, исправляется TXT по звуку. Дубликаты и ошибки файлов отмечаются; сложные записи не удаляются из оценки ради улучшения числа.

```powershell
# Сравнение: шесть dialog-файлов, по три повтора. dev01 используется для прогрева.
.\.venv\Scripts\python.exe scripts\compare_asr.py --dataset user_data\dataset-v1 --out user_data\selection-01 --executor "Юрий"

# Контроль: только выбранная конфигурация, два новых для неё control-файла.
.\.venv\Scripts\python.exe scripts\compare_asr.py --dataset user_data\dataset-v1 --out user_data\control-01 --split final_control --control-from user_data\selection-01\summary.json --executor "Юрий"
```

Для Михаила создаётся собственная папка результатов и указывается действительный исполнитель. Скрипт отказывается перезаписывать уже существующий прогон. Если код или данные изменились после выбора, контроль требует нового согласованного прогона.

Общий путь — `Session.process_file`, он же вызывается из GUI. Каждый распознаватель получает весь одинаково подготовленный звук и одинаковые фрагменты до 20 секунд, без пропусков отсчётов. Время включает полное чтение/декодирование и распознавание, загрузка модели измеряется отдельно. Ручное исправление текста не участвует в WER.

Результаты: `freeze.json` (версии/данные/условия), `summary.json` и `summary.md`, папки моделей с каждым исходным результатом, консолью и ошибками. Основная метрика — суммарный WER; дополнительно секунды, RTF, пиковая RSS и число сбоев. Повторения одной записи не являются независимыми случаями.

Правило выбора и ограничения описаны в плане. Числовой формат не исправляется по смыслу; различия «восемь»/«8» отражаются в строгом WER и требуют объяснения при разборе. Контрольные файлы не используются для выбора настроек. Один человек в тихой комнате не представляет все голоса и условия больницы.

## Быстрые тесты и пользовательская проверка

```powershell
.\.venv\Scripts\python.exe scripts\check.py --out user_data\my-checks-01
```

Это небольшой набор поведения приложения с подменой внешнего ASR/микрофона, а также проверки реальных файлов, сохранения и расчёта WER на известном примере. Он не измеряет качество настоящих моделей. Для минимальной среды тестов достаточно Python с Tkinter, `av==16.0.1`, `numpy==2.2.6`.

Инструментальная проверка настоящего окна:

```powershell
.\.venv\Scripts\python.exe scripts\check_gui_scenario.py

# Тот же сценарий с настоящим распознавателем
.\.venv\Scripts\python.exe scripts\check_gui_scenario.py --model whisper-small --audio data\audio\dev01.wav --out user_data\gui-real-01
```

Такой автоматический сценарий не является вашим ручным тестом. Карточки самостоятельного выполнения — [docs/manual-tests.md](docs/manual-tests.md). Заполняйте действия, наблюдения, исполнителя, дату и версию после реального выполнения.
