# Итоговый отчёт по модулю полной транскрибации

ДЗ №1 Коцура · версия 0.2 · 25 октября 2026 года.

Авторы ВКР: Юрий Черных и Михаил Бурундуков. Научный руководитель: Захарова Ирина Гелиевна. Заказчик ВКР: ОКБ №1. Код, инструментальные проверки и данный технический отчёт подготовлены агентом; личное выполнение студентами и приёмка врачом отдельно не заявлены.

## 1. Результат

Реализован сценарий: явно записать разговор или импортировать файл → получить полный русский текст → проверить и исправить → сохранить JSON/TXT и восстановить правки. Qwen и распределение по разделам формы исключены из обязательной цепочки по решению пользователя. Это законченный учебный этап ВКР, не готовая система заполнения протокола.

Сравнены восемь локальных CPU-конфигураций: 144/144 основных обработки завершены. Выбрана GigaAM v3 CTC в конкретном int8 ONNX-экспорте: WER 4.79%, медиана 0.537 с, RTF 0.0255. RNN-T имеет такой же WER, но больший медианный RTF. На двух контрольных записях выбранного CTC: 6/6 обработок, WER 0%. Нулевой WER на двух записях не является доказательством безошибочности или пригодности для больницы.

Пройдены 15/15 быстрых тестов локально и в GitHub Actions; выполнен настоящий GUI круговой сценарий с выбранной моделью. Микрофон физически агентом не включался. Личные ручные M01–M08, врачебная приёмка и презентация остаются действиями студентов.

## 3. Разработка и выбор процесса

Выбрана инкрементная модель с итерациями: новые возможности поставляются частями, уже созданные уточняются по проверкам и обратной связи. Зафиксировано реальное изменение границ в переписке: от обязательного извлечения по разделам к полному тексту. Каскад допустим при устойчивом фиксированном объёме; здесь пришлось бы пересогласовывать ранние решения. Это практическое основание выбора, а не утверждение, что каскад «всегда плохой».

Agile - ценности и принципы обратной связи и поставки, GitHub - инструмент. Для двух человек предложен ограниченный поток задач Kanban; существование полной доски и её статистики не заявлено. Прототип интерфейса помогает уточнять поведение. Полный Scrum/XP/DSDM не вводится ради названия. TDD использован на отдельных публичных границах; red-логи содержат также отсутствие нового API, поэтому в защите лучше подробно показать T13 с принятием дубликата до исправления. CI запускает быстрые тесты при push/PR.

Точные требования и критерии - asr-plan.md; объяснение моделей, жизненного цикла, Agile, требований, качества и данных - asr-explanation.md. Необходимо уметь связать каждое название с конкретным примером из исходников.

## 5. Условия и метод измерения

Windows 10 build 19045; Python 3.12.14; AMD Ryzen 7 5800H with Radeon Graphics, 8 физических / 16 логических ядер, RAM 15.40 GiB. CPU, восемь запрошенных потоков, где backend позволяет; Vosk управляет внутренней параллельностью иначе. GPU не использовался.

Версия обработки: commit `fd7345575d68ee3c4e46c0df49089ad99cf2a114`; SHA фактических исходников `f5245b72534f0acaaca28d0876aa19a463e0bbd85e6d8f0aef893264f67e8bdf`. Каждой модели - отдельный последовательный процесс. Загрузка/проверка весов измерена отдельно; далее прогрев на dev01, затем шесть файлов по три раза в фиксированном порядке. Время вокруг Session.process_file включает предварительную проверку, полное декодирование, общую фрагментацию и распознавание. Ручная правка, время действий в окне и вывод JSON измерения не входят. Замер не является строго холодным стартом: файловый кеш ОС не очищался. Питание/температура и фон ОС специально не контролировались; различия времени оцениваются как наблюдение на этом запуске.

Полный звук делится на одинаковые участки не более 20 секунд; у низкоэнергетической границы оставляется хвост не короче 6 секунд, без потери/повтора отсчётов. Разрез может повлиять на слова возле границы. Whisper: CPU int8, beam=5, ru, temperature=0, VAD=False; GigaAM: ONNX int8 CPU greedy; Vosk: собственный decoder. Это сравнение выбранных конфигураций, не изоляция одной архитектурной переменной.

WER=(замены+пропуски+вставки)/число слов. Нормализация едина: регистр, ё/е, пунктуация/пробелы; смысловой пересчёт чисел не делается. Сначала суммируем ошибки и N, затем делим. WER не учитывает медицинскую важность слова. RTF=секунды/длительность данного файла. Пиковая RSS - память всего worker, опрос 20 мс. Загрузка включает проверку SHA и создание backend; очень короткие пики и вклад кеша ОС полностью не контролируются.

Правило выбора зафиксировано до запуска: только успешно завершившие все попытки; минимальный общий WER; при точном равенстве - медианный RTF, затем RSS. Границы приемлемости для рабочего места врача не придуманы. Скачивание моделей завершено до основного сравнения.

## 7. Контроль и разбор ошибок

Контроль выполнен только CTC, после выбора и при совпадении исходников, набора, весов и потоков. Две записи, три повтора: 0/207 слов с повторами, то есть 0/69 слов двух разных записей. Медиана обработки 0,671 с, RTF 0,0268, RSS 375,9 MiB. Другие модели на control не запускались. Это малый результат одного читателя; нельзя писать «100% точность в больнице».

## 8. Отчёт о тестировании TR-ASR-02

Идентификатор: TR-ASR-02. Связанный план: TP-ASR-02. Цель: проверить поведение модуля и измерить ASR на согласованном наборе. Исполнитель инструментальных проверок: агент. Авторская сверка эталонов: Юрий. Личная ручная проверка студентов/врача: пока не проведена.

Объект/версия/среда: разделы 1 и 5, точный source_sha выше. Покрытие: FR01–FR07/NFR01–NFR03 с ограничением реального микрофона и пользовательской приёмки. Действия: ревью, анализ типов, 15 автоматических тестов, восемь dev-проб, 144 основных и 6 контрольных обработок, инструментальный GUI со спасением/открытием результата. Настоящее качество моделей не проверяется подставными ответами быстрых тестов.

Результат: локальные tests.log/summary.json - 15/15, ноль failures/errors/skips. GitHub Actions на исходниках fd7345575d68 - тоже 15/15, артефакт скачан и сверён по source_sha: [прогон](https://github.com/YuraVeseliy/medical-audio-mvp/actions/runs/40190223977). Анализ mypy: 14 исходных файлов без ошибок типов в выбранном режиме. pip check не нашёл нарушенных зависимостей.

GUI: настоящие импорт/кнопка обработки/модель/правка/JSON/TXT/новый/открытие, 94 прохода событий во время worker; исходник и правки восстановлены. Заменены только системные диалоги выбора пути/ошибки, чтобы сценарий выполнился воспроизводимо. Он не равен личному ручному тестированию. Повторный GUI выполнялся при запрете socket.connect/connect_ex/sendto до загрузки модели; попыток соединения не зарегистрировано. Сетевой адаптер ОС не отключался, M07 личного offline остаётся непроверенным.

Дефекты: прежние остановка записи и FLOAT WAV сохранены как регрессии; новые замечания целостности эксперимента исправлены до selection. Подробные карточки и доказательства - asr-defects.md. Основной и контрольный прогон завершены без ошибок выполнения; лексические ошибки ASR приведены отдельно.

Отклонения/ограничения: один читатель/диктофон, короткие тихие записи; нет разных пациентов/шумов/длинных реальных осмотров; нет личной ручной записи/приёмки, клинического порога и исследования экономии времени. Условия фиксированы в отчёте, но это не лабораторно контролируемое измерение температуры/питания. Прерванных основных процессов не было, аварийные ветви проверены искусственными случаями.

Решение: модуль пригоден для самостоятельной учебной демонстрации и повторной проверки. Готовность к больнице и окончательное выполнение ручной части ДЗ не подтверждены. Следующий шаг - Юрий и Михаил сами запускают тесты и M01–M08, фиксируют фактические наблюдения, после этого готовят презентацию. Согласование/подпись врача или преподавателя не подставляются.

## 9. Как повторить и что хранить

В репозитории нужна ветка asr-only-comparison; main сохраняет предыдущую версию до решения о слиянии. setup.cmd ставит зависимости и выбранную конфигурацию; launch.cmd открывает приложение. Папки с весами и личными записями в Git не включены. Локальные ярлыки запуска используют уже подготовленное окружение; на другом ПК следует выполнить установку из README.

Для самостоятельных быстрых тестов выполнить `.\.venv\Scripts\python.exe scripts\check.py --out user_data\my-checks-01`. Прочитать вход/действие/assert каждого T01–T15, сохранить логи с фактическим исполнителем. Личные карточки - manual-tests.md. Сравнение повторяется по командам README в новой папке результатов с тем же набором; после изменения данных/настроек нельзя приписать старые цифры новой версии.

Публичные доказательства: reports/asr_checks, asr_ci, asr_gui_final, asr-tdd, asr-comparison; требования/план/разбор - docs/asr-*. Старые файлы final-report/homework-plan/bugs помечены архивом; прежние PDF с Qwen относятся к 22ab866. Актуальные PDF полной транскрибации имеют ASR в имени. Презентация автоматически не создаётся.
