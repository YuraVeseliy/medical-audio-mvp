# Публикация аудиомодуля

Дата подготовки: 25 октября 2026 года. Публичный репозиторий: https://github.com/YuraVeseliy/medical-audio-mvp.

За основу взят текущий снимок аудиомодуля из локальной ветки `homework/audio-dialogue`, коммит `0b2fe4806b7e2b2445b0656f8285afdaddd6e3a2`. Старая история приватного `medical-form-mvp` не публикуется и его ветки не изменяются. Новый репозиторий имеет самостоятельную историю, поэтому слияния со старой реализацией проверки формы и разрешение её конфликтов не требуются.

Включены все 782 отслеживаемых исходных файла: приложение, 11 быстрых тестов, сценарии ручных проверок, учебные записи и эталоны, первичные результаты сравнений, логи циклов TDD, отчёты о дефектах, итоговый план и отчёт (Markdown и PDF), уведомления о сторонних компонентах. Добавлена эта памятка, обновлены инструкции получения проекта, название шага CI и исключения секретных файлов. Код приложения и тестов при публикации не менялся. `.gitattributes` сохраняет исходные байты файлов при клонировании, чтобы контрольные суммы оставались сопоставимыми.

Старые SHA коммитов в отчётах описывают исходную локальную историю: это не SHA нового публичного репозитория. Логи не переписывались под новую публикацию. Для сопоставления проверяйте `source_sha256`, хеши данных, версии компонентов и условия в сохранённых результатах. Публикация сама по себе не является новым прогоном тестов и не подтверждает ручную приёмку.

В Git не включены `.venv/`, `.runtime/`, пользовательские сеансы, голосовая модель Piper и готовая Windows-сборка. Модели и среда устанавливаются через `setup.cmd`. Источники, версии, контрольные суммы и лицензионные условия описаны в скриптах установки, отчётах и уведомлениях. Все включённые диалоги вымышлены; учебные WAV созданы синтетически. Они не являются записями пациентов.

## Что делать Михаилу

1. Клонировать репозиторий или скачать Code → Download ZIP.
2. Для запуска приложения установить Python 3.12 x64 с Tcl/Tk, выполнить `setup.cmd`, затем `launch.cmd`.
3. Для самостоятельного прогона быстрых тестов выполнить `.\.venv\Scripts\python.exe scripts\check.py`. Модели и микрофон этому набору не нужны; для минимальной среды достаточно Python с Tkinter и `av==16.0.1`.
4. Перед запуском сохранить предыдущую папку `reports/checks`, поскольку команда перезаписывает лог и сводку. Записать своего исполнителя, время, версию и фактический результат. Чужой сохранённый лог не является вашим личным прогоном.
5. Пройти `docs/manual-tests.md` и заполнить фактические результаты. Эти карточки не считаются выполненными заранее.
6. Для совместных изменений создавать отдельную ветку и pull request. Публичная видимость даёт возможность читать и делать fork; для прямой записи в общий репозиторий владельцу нужно пригласить GitHub-аккаунт Михаила в collaborators.

Открытый дефект D05 (неверный выбор реплик и разделов моделью) сохранён. Прототип требует проверки текста человеком и не считается принятым для работы с пациентами.
