# Личные ручные проверки модуля транскрибации

Версия формы: 0.2, 25.10.2026. Все случаи пока ожидают личного выполнения студентами. Программные GUI-сценарии агента и логи CI не заполняют эти поля за вас.

До начала: записать коммит/хеш исходников, ОС, Python, CPU/RAM, модель/ревизию, устройство записи, SHA аудиофайла и условия. Использовать вымышленные диалоги. В каждом случае заполнить фактический результат, статус, исполнителя, дату и доказательство. При расхождении создать дефект: шаги, вход, ожидаемое/фактическое поведение, версия, серьёзность, приоритет и лог/снимок.

## M01. Загрузка и полная расшифровка

Предусловия: установлена выбранная модель; аудио и проверенный TXT доступны.
Шаги: открыть приложение, выбрать модель, загрузить запись, нажать обработку, дождаться результата. Сверить начало, середину и конец с записью; отметить ошибки слов.
Ожидается: весь файл обработан; исходный и редактируемый тексты доступны, окно отвечает на действия. Ошибки ASR записываются как результат сравнения, а пропажа части файла — как дефект обработки.
Факт / статус / исполнитель / дата / доказательство: **не заполнены**.

## M02. Правка, экспорт и восстановление

Шаги: после M01 исправить слово справа, проверить неизменность исходника слева, сохранить JSON и TXT. Открыть TXT в Блокноте. Начать новый сеанс и открыть JSON.
Ожидается: TXT содержит текущий исправленный текст; JSON восстанавливает и исходный результат, и правки, и выбранную модель.
Факт / статус / исполнитель / дата / доказательство: **не заполнены**.

## M03. Защита несохранённого текста

Шаги: изменить текст, нажать «Новый сеанс», выбрать «Отмена». Повторить и выбрать сохранение. Отдельно проверить явный отказ от сохранения на ненужном учебном результате.
Ожидается: отмена сохраняет текст в окне; выбор сохранения действительно создаёт файл; отказ очищает только после явного решения.
Факт / статус / исполнитель / дата / доказательство: **не заполнены**.

## M04. Настоящая запись с микрофона

Шаги: обновить устройства, выбрать микрофон, начать запись вымышленного диалога, остановить. В диалоге выбора пути нажать отмену; проверить, что запись не продолжается. Затем сохранить буфер и прослушать WAV. Обработать его.
Ожидается: захват начинается только по кнопке, заканчивается перед выбором пути; сохранённый звук доступен. Реальные обе реплики слышны; устройство и настройки указаны.
Факт / статус / исполнитель / дата / доказательство: **не заполнены**.

## M05. Ошибка файла и повтор

Шаги: выбрать повреждённый учебный аудиофайл; получить сообщение. Затем выбрать правильный файл и обработать.
Ожидается: понятная ошибка, прежний результат не выдаётся за новый; после ошибки обработка возможна.
Факт / статус / исполнитель / дата / доказательство: **не заполнены**.

## M06. Модель не установлена и смена конфигурации

Шаги: выбрать ещё не установленную модель и начать обработку. Зафиксировать сообщение. Установить её отдельной командой, снова выбрать и повторить обработку.
Ожидается: приложение сообщает о подготовке модели; не отправляет речь в облако и не начинает скрытую установку. После установки работает выбранная конфигурация, имя в сохранённом JSON соответствует ей.
Факт / статус / исполнитель / дата / доказательство: **не заполнены**.

## M07. Работа без интернета после подготовки

Шаги: после установки моделей самостоятельно отключить интернет средствами ОС, открыть приложение и обработать учебную запись. Сохранить результат, затем вернуть сеть.
Ожидается: подготовленная локальная модель работает. Само отсутствие сетевого запроса в коде не заменяет этот личный прогон.
Факт / статус / исполнитель / дата / доказательство: **не заполнены**.

## M08. Отзывчивость и удобство

Шаги: второму участнику без подсказок дать задание «загрузить → распознать → исправить → сохранить». Во время обработки переместить окно, изменить размер, попробовать начать вторую обработку.
Ожидается: окно отвечает, конфликтующая операция недоступна, участник находит сохранение. Записать реальные затруднения и время, не ставить оценку удобства заранее.
Факт / статус / исполнитель / дата / доказательство: **не заполнены**.

## Исправление и регрессия

После найденного дефекта повторить именно исходный случай — это проверка исправления. Затем выполнить затронутые соседние случаи и быстрый набор — это регрессия. Результат относится к указанной версии и среде; после изменений старый лог сам по себе не подтверждает новую версию.
